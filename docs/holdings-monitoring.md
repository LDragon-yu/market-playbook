# 持仓、盘中哨兵与个股问答

本模块只做决策辅助，不连接券商、不自动下单。硬规则负责行情时效、T+1、风险事件和空仓门槛；大模型只在这些约束内解释证据。

## 推荐工作流

1. 交易日 17:10 运行 `python -m scripts.job post-market`，同步行业/概念分类并生成次日监控池。
2. 盘前先在 Web 的“持仓监控”录入总数量、可卖数量、成本、买入日期、买入逻辑与失效条件。
3. 导入外围、消息和自媒体信息后，于 08:20 运行 `python -m scripts.job pre-market`。预案会先处理高风险持仓，再判断能否开新仓。
4. 盘中在“持仓监控”手动检查，或启用后台轮询。重点监控持仓、情绪龙、板块确认股、同板块二选一、跨板块卡位和市场空间板。
5. 在“个股问答”中询问具体股票。回答会引用单股快照、持仓、板块角色、预案和情报，并标明数据时间。

## 自动监控配置

```dotenv
MONITOR_ENABLED=true
MONITOR_INTERVAL_SECONDS=60
MONITOR_MAX_SYMBOLS=18
```

当前第三方代理不支持全市场批量快照，因此系统按优先级逐股请求 `rt_k`。18 只股票一轮可能耗时约 20–60 秒，取决于供应商速度与限流。不要把间隔设得短于 20 秒，也不要直接扩展为全市场轮询。

后台轮询只在工作日 09:25–11:30、13:00–14:56 运行，而且要求数据库中已有当天盘前预案。节假日仍建议由云平台交易日历停用任务。

Web 监控页打开时每 15 秒拉取一次新预警；点击“浏览器提醒”并授权后可显示系统通知。云端必须使用 HTTPS（localhost 除外），关闭页面后不会继续发送浏览器通知；如需离线推送，应后续接入企业微信、飞书或短信通道。

系统会拒绝用上一交易日快照触发实时告警或卡位结论。同一股票的同类持续风险默认五分钟内只记录一次；涨停打开、日内高点大幅回撤、接近日内低位、接近跌停及 T+1 锁定会进入预警。

## T+1 口径

- `总股数` 是当前全部持仓；`可卖股数` 是当天实际可卖数量。
- 买入日期为今天时，服务端强制可卖数量为 0。
- 买入日期早于今天且可卖数量留 0 时，MVP 默认全部可卖。
- 分批买入、部分冻结等复杂情况，请手工填写准确的可卖数量。
- 即使风险触发，无可卖数量时也只会输出“停止加仓/风险锁定”，不会生成虚假的卖出动作。

## 大模型配置

```dotenv
LLM_ENABLED=true
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=你的Key
LLM_MODEL=deepseek-chat
```

可替换为兼容 Chat Completions 与 JSON 输出的服务。模型动作被限制在观察、停止加仓、取消买入、降低预期、条件减仓/退出、切换观察、保持空仓和信息不足。模型超时、返回非法动作或服务异常时，系统自动回退到硬规则。

不要把 API Key 写进前端、README 或截图。修改 `.env` 后需要重启服务。

## 常用命令

```powershell
python -m scripts.monitor enrich
python -m scripts.monitor build-watchlist
python -m scripts.monitor monitor-once
```

首次接入真实数据建议保持 `MONITOR_ENABLED=false`，先连续手动检查几轮并与行情终端核对时间、价格和涨跌停价，再开启自动轮询。
